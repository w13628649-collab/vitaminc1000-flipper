# 交易模型:口径与设计决策

这份文档记的是口径和取舍——为什么这么算,不是怎么用。接口和部署见
[progress.md](progress.md)。

第一版是个 Python demo,只做同城、只有一种执行方式、只给一张排序表。
现在的模型比它宽得多:

| 维度 | demo | 现在 |
|---|---|---|
| 执行方式 | 挂买挂卖一种,固定 9% 摩擦 | 市价/挂单四种组合,摩擦 4%–9% |
| 空间 | 同城 | 同城 + 跨城套利 |
| 成交量约束 | 单边 | 跨城两端都要看 |
| 风险 | 无 | 波动率、价格 z-score、销地高位预警 |
| 成交价 | 用最优价 | 吃深度算真实加权均价和滑点 |
| 资金 | 一张排序表 | 资金预算 + 边际收益曲线 |
| 闭环 | 无 | 记账反推 `absorb_ratio` |

## 执行方式:demo 漏掉的一整类机会

一次往返有两条腿,每条腿可以吃单(市价)也可以挂单(限价),四种组合:

| 模式 | 摩擦 | 代价 |
|---|---|---|
| 秒买秒卖 | **4%** | 付卖一、收买一,吃掉整个盘口宽度 |
| 秒买挂卖 | 6.5% | 货立刻到手,卖单挂着等 |
| 挂买秒卖 | 6.5% | 买单挂着等,拿到货立刻脱手 |
| 挂买挂卖 | 9% | 价格最好,两头都要等成交 |

费用结构:**买方吃单不付任何费用**;卖出永远交 4% 市场税;挂单(买卖都算)
另收 2.5% 创建费,不退。

demo 只建模了最后一行。但秒买秒卖的摩擦只有它的一半还不到——盘口窄的时候
省下的手续费不够赔进去的价差,盘口宽的时候就反过来了。**这个选择不该由代码
替用户做**,所以四种全算出来摆在界面上,标出哪个最赚,用户自己挑。

跨城尤其吃这一套:两地价差常常比盘口宽度大一个数量级,这时候秒买秒卖
既省 5% 手续费又不用在两头各等一次成交。

## 跨城:demo 排除掉的那一半

demo 不做跨城,理由是"钱锁在路上,跟现金流健康冲突"。这个理由只对了一半——
锁的是**时间**,不是资金效率。实测下来跨城的日收益经常是同城最优的两倍。

三件事必须算进去:

1. **两端都要有量。** 产地进得去、销地也得出得来,取两边可吃量的较小值。
   只看一边是这类工具最常见的高估来源。界面上那个"产地量/销地量/本金"
   标签就是在说瓶颈在哪
2. **运输时间只在本金撑不满市场容量时才影响日收益。** 本金够一趟吃下一整天的量,
   跑得再快也没有更多货给你搬;本金只够吃一小口,跑得快才能多周转几轮。
   这一条容易想反
3. **troll 判断看原始价格比,不看毛利率。** 同一对价格用不同执行方式算出的毛利
   差一截,挑最赚的那个模式反而最容易撞上毛利上限,整条路线就被误杀了。
   所以价格比超过 3 倍直接判假单,和执行方式无关

路上被劫、货砸手里这类风险**不建模成数字**——那是玩家自己的判断,
工具能做的是把量、价、时间摆清楚。

## 风险:同样的价差不是同样的机会

三个数,都来自 30 日成交历史:

- **变异系数 CV** = 标准差 / 均价。跨品种可比:3000 银的货波动 300
  和 300 银的货波动 300,完全不是一回事
- **z-score** = (当前中价 − 30 日均价) / 标准差。负得多说明现在便宜,
  是均值回归的买点;正得多说明现在贵,这个价差**可能只是一时的**——
  跨城路线的销地 z 超过 1.5σ 会直接降级到低可信度
- **回归趋势 + R²**。一路下跌的品种,今天的价差明天可能就没了

标准差按成交量加权:一个只成交 3 件的异常日不该和万笔成交日
对波动率有同等话语权。

## 吃深度:最优价只是第一件的价格

要买 5000 件就得往下吃好几档,真实成交均价一定比卖一差。只看最优价会
**系统性高估每一条机会,而且量越大高估得越厉害**。

实测例子(模拟数据):某城 T5 钢锭卖一 1181,但那个价上只有 6 件;
买满 1000 件的实际均价是 1214,滑点 2.8%。

这是抓包数据独有的能力。AODP 的 prices 端点只给价格不给数量,
拿它根本算不出这件事——查价页上那两列写着"需要抓包"的格子,
就是在说这件事。

## 资金:一张排序表回答不了"钱怎么分"

每条机会算出来的"可吃量"都假设**全部本金投在它一个人身上**,
所以那一列加起来远超总资金,照着做会发现钱不够。

资金预算按风险调整后的**回报率**(不是绝对收益)从高到低贪心分配,
每条只给它真正吃得下的那部分。三个约束:

- **单条上限**(默认 25%):不设的话钱全砸在第一条上,而"可吃量"
  本身只是个估计值,估错一次就全军覆没
- **风险厌恶系数 λ**:按 `回报率 / (1 + λ×变异系数)` 排序。λ=0 就是纯看收益
- **最小仓位**:太小的单子不值得单独开一条

输出是累计投入 vs 累计日收益的曲线。它一定是凹的——边际收益递减到
哪里就该停手,一眼能看出来。**钱花不完不是 bug**,是市场深度不够,
界面会明说。

## 闭环:唯一能自我修正的地方

所有估算里最虚的那个数是 `absorb_ratio`(敢吃日成交量的多大比例),
配置里是拍脑袋的 0.20。别的数字都来自市场快照,只有记账表知道
"照着模型下的单,实际成交了多少"。

记一笔:计划量、计划买卖价、当时模型估的日成交量。收口时填实际成交。
系统给出三个数:

- **成交率** = 实际吃到 / 计划量
- **实测 absorb_ratio** = 实际吃到 / 当时的市场日成交量
- **模型准确度** = 实际净利 / 计划净利

跑几十笔之后,这三个数比任何理论推导都可信。

## 数据从哪来

两个来源,抓包优先:

| 来源 | 有什么 | 缺什么 |
|---|---|---|
| 公会成员抓包 | 挂单价 **+ 数量**,秒级新鲜 | 只覆盖有人去翻过的物品和城市 |
| AODP REST | 全服众包,覆盖广 | **不返回挂单数量**,亚服数据常常几小时旧 |

AODP 拿不到数量,这正是 troll 过滤必须存在的根本原因:"最低卖价 1000"
可能只对应 1 件货。抓包有数量,查价页上那一列就是它的价值。

两边的成交历史(AODP 的 `history` 和抓包的 `markethistories`)是**同一份
服务端数据**,同一个桶里只能二选一,取平均会重复计数。库里按 `source` 区分,
读的时候优先取抓包那条。

## 亚服数据覆盖率才是真瓶颈

不是算法。首次实测(66 物品 × 6 城):

| 城市 | 6 小时内有数据 | 中位年龄 |
|---|---|---|
| Fort Sterling | 29/66 | 6.9h |
| Caerleon | 30/48 | 3.3h |
| Lymhurst | 18/42 | 6.9h |
| Bridgewatch | 15/59 | 6.8h |
| Martlock | 6/43 | 6.8h |
| Thetford | 1/36 | 6.9h |

拒绝原因里 **`one_sided` 占绝大多数**——不是价格不好,是根本没有双边报价。
公会自己的抓包客户端就是为了补这一块。界面顶部那排覆盖率条按这个画。

## 几个设计决策

SPEC 之外、实现时做的判断,都会影响结果,列在这里备查。

### 单条机会的排序主键是日化**绝对**收益

`daily_profit = profit_per_unit × min(可吃量, 本金买得起的量)`。

毛利率单独看区分不出东西:同城假设一天一轮,`daily_roi` 数值上就等于单笔毛利率。

**但资金分配那一步反过来按回报率排。** 这不矛盾:看单条机会时问的是
"这条值多少钱",绝对收益才是答案;分配有限资金时问的是"这一银放哪里效率最高",
那就得看回报率。两个问题,两种排序。

### Troll 过滤比 SPEC 多一层

SPEC 的四层(新鲜度 / 偏离度 / 成交量 / 双边确认)有个缺口:
买价偏离 0.45x、卖价偏离 2.4x,**各自都在 [0.4, 2.5] 内合规**,组合起来却是 5 倍价差
—— 两边同时是 troll 单。所以加了第五层 `max_margin`(默认 100%)。

跨城不用这一层,改用原始价格比——原因见上面「跨城」那节。

另外还拦**交叉盘**(买价 ≥ 卖价):真实市场不会持续存在这种状态,出现说明
两侧快照来自不同时间,是陈旧数据的强信号。可以用 `reject_crossed_book: false` 改成只降级。

### 偏离度阈值的实测标定

首次实测(66 物品 × 6 城,160 个有效价格点)的偏离度分布:

```
min 0.48x | p25 0.89x | p50 0.96x | p75 1.02x | p99 1.51x | max 1.56x
落在 [0.4, 2.5] 外的:0 条
```

**SPEC 给的 [0.4, 2.5] 对当前这批物品一条都拦不住** —— 高流动性精炼材料和
常见装备上的 troll 单会被真实挂单迅速淹没,真正在起作用的是新鲜度和单边过滤。

阈值先按 SPEC 保留不动,因为它是防守性的:一旦把物品范围扩到低流动性品类
或附魔装备,troll 单就会出现。想更贴合实测就收到 `[0.6, 1.8]`,代价是
可能误杀真实的价格波动。**扩物品范围时记得回头看这组分布。**

### 挂单价不等于现价

挂在现价上只能跟人并排排队,得等前面的人先成交。要真排到队首,
买单得高 `outbid_silver`,卖单得低 `undercut_silver`(默认各 1 银)。
成本很小,但不算进去会系统性高估所有机会。表格里的 **`挂买→挂卖`** 就是
要去游戏里照着填的两个数。

### 日均成交量的分母是"有数据的天数",不是窗口长度

AODP 缺失某天几乎总是"那天没人上传",不是"那天没成交"。按 7 天平均会把
覆盖率问题误算成流动性问题。代价是样本少时噪声大,用 `min_days_with_data_7d` 兜底。

同理,**当天那个点会被丢掉** —— 它是还没走完的一天,量必然偏低。

### 均价按成交量加权

算术平均会让一个零星成交日和一个万笔成交日等权,基准均价被带偏后,
偏离度过滤就会失准。

## 摩擦成本

```
市场税 4%(premium) + 挂卖单 2.5% + 挂买单 2.5% = 9%
```

**挂买单收 2.5% 已经确认**:游戏本地化文本里买单和卖单都有
`MARKETPLACE_*ORDER_LABEL_SETUP_COST`,中文管这项叫"创建费"。
所以往返摩擦是 9%,不是 6.5%。

另注:游戏里有装备能减拍卖税(`@ITEMDETAILS_STATS_AUCTION_TAX_REDUCTION`),
税率不是固定常量;走私贩网络还另收距离税费。这两个都还没建模。

## 输出口径

`confidence` 三档:

- `high` —— 双边数据都在 2 小时内
- `medium` —— 在 6 小时内
- `low` —— 任一指标贴近过滤阈值边缘(具体哪一项在 `warnings` 里)

被拦下的候选不会丢掉,`rejected` 里带着原因和细节,界面底部会汇总。
这样能回答"为什么我没看到某物品",而不是只能干瞪眼。

## 销量榜的趋势怎么判

最小二乘拟合,不是首尾相减。某天有人挂了个离谱均价,首尾相减整条趋势就反了。

R² 一起看:低于 0.3 就判 `choppy`,斜率再陡也只是噪声。涨跌幅绝对值小于 4%
判 `flat`。

**基准取拟合直线的起点,不是窗口均值。** 用均值当分母时,一条从 300 跌到 10
的线会算出 -187%,跌幅超过 100% 说不通。

全服口径下同一天有多城数据,先按成交量加权成一个日均价再谈趋势。不然两城
价格差一截时,折线会在两个水平之间来回跳,看着像震荡。

## 物品目录

`ao-bin-dumps` 两份 dump 合并:`formatted/items.json` 给官方中英文名和完整的
附魔变体 ID,根目录 `items.json` 给市场分类树、tier、品质档数(不含附魔变体,
所以附魔物品的分类要剥掉 `@N` 后查本体)。

分类的中文名来自 90MB 的 `localization.json`,极少变动,**随二进制带着**
(`internal/catalog/data/categories.json`,6KB),不值得每次同步都下一遍。

**物品族**是去掉等级前缀、附魔后缀和材料 `_LEVELn` 中缀后剩下的骨架。族名取
成员名字的最长公共后缀——一族里各等级只差一个前缀(新手级/学徒级/老手级…),
公共后缀正好是族名,不用硬编码等级前缀表。两个坑:

- **只要求多数成员满足**(≥70%),不是全部。火焰法杖那族里混着一件叫
  「Vendetta之怒」的特殊武器,按全员取交集会把后缀打成空字符串
- 材料不吃这套。细布/精布/华布 的公共后缀只剩一个"布"字,金属锭更是只剩
  "条"。退化成一两个字就改用这族里最低等级那件的全名——"钢条"比"条"认得出来

图标存 PG 的 `item_icon`(BYTEA)。不存的话,翻一页分类就是上百个并发请求直打
`render.albiononline.com`,会被对面限流,列表里一半图标是空的。

## 还没做

- **进游戏核对。** 随机抽 5 条照着挂,看实际能不能成。这是整套模型
  唯一还没被现实检验过的地方——记账页就是为它准备的
- **跟 AlbionSnipe / AlbionKit 交叉对比。** 对不上的地方就是过滤逻辑的缺口
- **运输时间还是个常数**(默认一趟 1 小时)。应该按城市对的实际距离算,
  黑区路线还要另算风险
- **金价没接。** 白银在通胀时,持货比持银强,这个判断现在做不了
- **跨城的历史价差没存。** 现在只能看当下的价差,看不出"这条路线
  是长期存在还是今天才出现"。存下来之后才能判断哪些是结构性的
