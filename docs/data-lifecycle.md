# 抓到的数据存什么、存多久(提案,2026-10-19)

明文全抓之后,写库的只有原始样本(每个 (方向, 码) 每次运行最多 20 条,库里每码留 200 条)。
其余消息要不要落盘、落多久,按类型分四层。

## 四层

| 层 | 存哪 | 存多久 | 例子 |
|---|---|---|---|
| 原始样本 | 服务端 `capture_sample` | 每码滚动 200 条 | 所有消息(已做,`f202ce1`) |
| 当前地图 | 客户端内存 | 离开这张图就清 | 怪、资源点、附近的人 |
| 自带过期 | 库,带到期时间 | 到期作废 | 阿瓦隆之路的门(12–24 小时)、实时挂单、工作站费率 |
| 永久 | 库 | 永久 | 市场成交历史、个人账本 |

阿瓦隆之路的门放第三层:走过的门都记下来、到点作废,就能拼出一张自己的路网,
"从这里到最近一个有王座的图要走几步"就能算。

## 个人账本

| 想知道的 | 消息 |
|---|---|
| 银币多少 | 事件 81 `UpdateMoney`(还有 85 `UpdateCurrency`) |
| 仓库存货 | 操作 520 `AssetOverview` 系列(520–527,资产总览一次给全部城市全部仓库);事件 413 `BankVaultInfo`、99 `AttachItemContainer` |
| 买了什么、什么价 | 操作 83 `AuctionBuyOffer`(吃卖单) |
| 卖了什么、什么价 | 操作 88 `AuctionSellRequest`、315 `AuctionSellSpecificItemRequest`(吃买单) |
| 挂单 | 操作 79 `AuctionCreateOffer`、80 `AuctionCreateRequest` |
| 改价、撤单 | 操作 85 `AuctionModifyAuction`;84 / 86 / 87 撤单 |
| 还挂着多少 | 操作 92 `AuctionGetMyOpenOffers`、93 `...Requests`、94 `...Auctions` |
| 卖出去没有 | 操作 89 `AuctionGetFinishedAuctions`、493 `AuctionFetchFinishedAuctions`、91 `AuctionFetchAuction` |
| 成交通知 | 操作 174 `GetMailInfos`、176 `ReadMail` |
| 和玩家直接交易 | 操作 161–167、事件 175–180 |

市场挂单的 `AuctionDTO`(21 个字段)带卖家/买家 id、数量、价格、取货状态。
"我的订单"系列很可能是同一个格式,现成的挂单解析器能复用——等样本确认。

量很小:一个人一天几百条,吞吐不是问题。

**它能补上项目里两个最虚的数:**

- **挂单没成交的损失**:创建费 2.5% 下单就扣、不退,CLAUDE.md 里写着"这一项目前在模型里还是 0"
- **敢吃多少成交量**:`absorb_ratio` 现在是拍脑袋的 0.20。`trade` 表(0005_journal.sql)
  就是为了校准它建的,但要手填。账本能自动填它的"实际成交"那一半

**必须按自然键去重。** 同一批订单每次打开"我的订单"都会再发一遍,"已完成"列表在取货前
每次打开也会重复出现;多张网卡同时抓时同一条消息也可能被解两次。账本按订单 id 这类
自然键入库,不然一笔会记成好几笔。

## OpenRadar 能拿的(MIT)

| 拿 | 为什么 |
|---|---|
| 录包、离线回放、真实录包做回归测试 | 它按场景切了 22 段真实录包放在测试目录,游戏一更新重跑就知道哪里漂了。我们一段都没有,测试全是手写数据,而现在要解的消息多了几百种 |
| 网卡分类 + ExitLag 提示(`internal/capture/categorize.go`) | 一个很小的文件,按网卡名认出 ExitLag / VPN / 虚拟网卡。认出 ExitLag 就提示改 NDIS 模式 |
| 运行中增减网卡(`internal/capture/manager.go`) | 开关加速器、换网线会让游戏流量换网卡。我们启动时定死网卡列表,换了要重启客户端 |

| 不拿 | 为什么 |
|---|---|
| Photon 解析层 | 我们的分片重组按分片序号去重、按总片数判完成,有待重组上限和超长保护,比它的严 |
| 码表 | 我们的从用户装的客户端里直接抽,它的从社区枚举生成 |
