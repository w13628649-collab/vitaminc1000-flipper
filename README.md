# albion-flipper

Albion 亚服(East)**同城价差扫描器**。按日化收益排序,带五层 troll 过滤。

需求见 [SPEC-flipper.md](SPEC-flipper.md),项目背景见 [CLAUDE.md](CLAUDE.md)。

## 上手

### Windows 免安装包

拿到 `albion-flipper-windows-*.zip` 的话,解压后**双击 `run.bat`** 就行 ——
不用装 Python,不用装依赖,浏览器会自动打开。

包里 `runtime\` 是一份独立的 Python 3.12(依赖已装好),`data\flipper.db`
已经带好 11391 个物品的中英文名、市场分类树和 408 个常用图标,解压即用。

| 脚本 | 用途 |
|---|---|
| `run.bat` | 启动 web 界面 |
| `test.bat` | 跑 74 个测试 |
| `cli.bat scan` / `cli.bat rank` / `cli.bat --help` | 命令行入口 |

源码在 `src/flipper/` 下,都是普通 Python 文件,**改完重启 `run.bat` 就生效**
(没有编译步骤)。要装新依赖:
`runtime\python.exe -m pip install 包名`,离线的话用 `--no-index --find-links vendor`。

### 从源码跑

```bash
uv venv --python 3.12
uv pip install -e .

flipper items sync     # 从 ao-bin-dumps 拉物品目录(首次必跑)
flipper serve          # web 界面 → http://127.0.0.1:8420
```

代码跑在远程机器上、浏览器在本地时,默认的 `127.0.0.1` 连不上,要改绑:

```bash
flipper serve --host 0.0.0.0        # 启动时会打印局域网地址
```

这个服务没有鉴权,绑 `0.0.0.0` 等于同网段谁都能打开并触发扫描。
内网机器上无所谓,公网 IP 上别这么开。

也可以全程走命令行:

```bash
flipper items list     # 看配置展开出哪些物品
flipper check          # 只看数据覆盖率 —— 亚服的真瓶颈在这里
flipper scan           # 扫描,输出终端表格 + CSV + SQLite
flipper history        # 抓成交历史入库(销量榜的数据来源)
flipper rank           # 销量排行榜
```

常用参数:

```bash
flipper scan --limit 40 --min-confidence medium    # 只看中高置信
flipper scan --city Lymhurst --city Martlock       # 只扫指定城市
flipper scan --max-age 12                          # 放宽新鲜度(慎用)
flipper scan --show-rejected --rejected-reason deviation   # 看 troll 过滤拦下了什么
flipper scan --csv out/today.csv
```

阈值全部在 [config.yaml](config.yaml)。**按实盘反馈改配置,不要改代码。**

## 中英文

物品名用 ao-bin-dumps 里的官方 `LocalizedNames["ZH-CN"]`,跟游戏内中文客户端完全一致
(`T4_CLOTH` → 细布,`T5_METALBAR` → 钛钢条)。终端表格、CSV、web 界面统一用中文,
搜索时中文名、英文名、物品 ID 三者都能命中。

**城市名不翻译。** 查过官方 localization:中文版里五大城市、Caerleon、Brecilien
全部保持英文原名,只有 Black Market 译作"黑市"。跟着游戏走,省得在界面和游戏之间
来回做脑内转换。

`flipper items sync` 会下上游两份 dump 写进库:

- `formatted/items.json`(24MB)有官方中英文名和完整的附魔变体 ID
- 根目录 `items.json`(17MB)有市场分类树、tier、品质档数,但**不含附魔变体**——
  所以附魔物品的分类要用剥掉 `@N` 后缀的本体 ID 去查

分类中文名(16 大类 / 97 子类)随包走,在 `src/flipper/data/categories.json`,只有 6KB。
它来自 `localization.json` 的 `@MARKETPLACEGUI_ROLLOUT_SHOPCATEGORY_*`,
但那个文件有 90MB 且极少变动,不值得让每个人 sync 时都下一遍。

游戏更新后重跑 `items sync`;真改了市场分类才需要重新生成 `categories.json`。

## 全都在一个库里

`data/flipper.db` 一个文件装下所有东西 —— 备份只要拷它:

| 表 | 内容 |
|---|---|
| `items` | 11391 个物品的中英文名、市场分类、物品族、tier、品质档数 |
| `categories` | 分类树(大类 / 子类,带中英文名和游戏内的排列顺序) |
| `icons` | 物品图标的 PNG,BLOB 直接存 |
| `history_daily` | 逐日成交量和均价,增量累积 —— 销量榜的数据源 |
| `scan_runs` / `opportunities` | 每次扫描的快照 |

固定不变的东西没有理由散在文件系统里。图标尤其:之前是 `data/icons/` 下上千个
小 PNG,现在是库里的 BLOB,连着物品目录一起备份。

## Web 界面

`flipper serve` 起一个**只绑 127.0.0.1** 的本地服务(`--host` 可改,见上面的上手部分)。
数据是本机的 SQLite 加实时 AODP 调用,没有对外服务的必要;这也正好落在 SBI 对
第三方工具的判断标准里——数据在网页上呈现,不是游戏内覆盖层。

几个和终端版不同的地方:

- **首屏是各城覆盖率,不是机会列表。** 条形分三段:2 小时内(青铜)、2 小时到新鲜度
  上限(城市色)、超出阈值(灰)。今天 Thetford 显示 `0/132 可用`,就别看那边的机会了。
- **数据越旧,那一行越褪色。** 旧数据看起来就该旧,不需要再挂一个红色警告。
- **贴着过滤阈值边缘的行带红色竖线**,并在下方说明是哪一项贴边——排序按日收益,
  最赚钱的那条经常也是最可疑的那条。
- **表里的物品名可以点**,直接跳到查价页看它在所有城市的价格,左边列表还会自动
  定位到它所在的分类。看到机会想查全城价,不用再去查价页重搜一遍
- **阈值即时可调**:新鲜度、本金、城市、置信度改完点重新扫描。
  `挂买单收 2.5%` 那个开关直接对应待验证项,关掉能立刻看到摩擦降到 6.5% 后多出多少机会。
- 机会少于 5 条时,过滤原因面板自动展开——那时候"为什么这么少"比"有哪几条"更重要。

界面用 Archivo 单字族;城市配色取自游戏里各城自己的代表色,不是随机分配的分类色。

### 查价页

照着游戏内市场做的浏览界面,但游戏里一次只能看当前所在城市的一个品质,
这一页把**所有城市 × 所有品质**摊成一张表,外加黑市和 7 日均价。

**分类菜单是三级联动的**,照着游戏内市场做:点开后鼠标指到「武器」,右边一栏
展开弓 / 十字弓 / 战斧……;指到「弓」,再右边一栏展开弓箭 / 长弓 / 战弓 / 破雾之弓。
三栏并排而不是层层弹出——嵌套弹窗在屏幕边缘会飞出去,并排列不会,而且三层同时可见。
任意一层都能点:点「武器」就筛整个大类,点到「长弓」就只看那一族。

第三级的**物品族**是把各等级归并出来的:`T4_2H_BOW` 到 `T8_2H_BOW` 连同附魔变体
算一族,族名取各等级名字的公共后缀(老手级**长弓** / 专家级**长弓** → 长弓)。
两个坑:一是火焰法杖那族混着一件叫「Vendetta之怒」的特殊武器,按全员取交集会把
后缀打成空串,所以只要求多数成员满足;二是材料不吃这套,细布 / 精布 / 华布 的公共
后缀只剩一个「布」字,退化成一两个字就改用最低等级那件的全名。

菜单右边还有**等级 / 附魔 / 品质**三个下拉。品质控制价格矩阵显示哪几列——
材料只有普通一档,这时它会自动置灰。

搜索框和分类互斥:一旦输入内容,分类菜单和等级、附魔下拉一起置灰,直接在全目录里搜。

- 搜索吃中文、英文、物品 ID;列表项带 tier 徽标和附魔等级(`.1` / `.2` / `.3`)
- 每格分两行,用的是游戏里市场那两个页签的说法:**卖单最低**是「销售订单」最上面
  那一行(别人挂着卖的最低价,你想马上买到货就付它);**买单最高**是「购买订单」
  最上面那一行(别人挂着收的最高价,你想马上出货就拿它)。
  所以卖单价总比买单价高,这段差就是利润空间
- 第三行的**同城价差**已经把 9% 的税和手续费扣掉了,就是在这座城挂买单收货、
  再挂卖单出货一轮下来的净毛利率。光给两个挂单价的话,人得自己心算才知道够不够吃摩擦
- 价差超过 100% 的标 ⚠ **红底**,不给绿色。这种数字通常不是机会,而是某一侧挂了
  troll 单——AODP 拿不到挂单数量,一张 1 件货的离谱报价和真实行情长得一模一样。
  扫描页有五层过滤拦着它们,查价页展示原始值,就得靠标色提醒
- 两侧**各报各的数据龄**——它们常常差十几个小时,混成一个数字会让人看不懂
  为什么一个标着 16.9h 的格子会被选成本档最便宜
- 超过新鲜度上限的时间标红;最低/最高标记只在新鲜数据里选
- **最低/最高只在同一品质内比。** 不同品质是不同的商品:一件卓越品质的长袍
  卖得比普通贵三倍,那不是价差,那是另一件东西
- **品质列头按游戏里的品质色着色**:普通灰 / 优秀绿 / 杰出蓝 / 卓越紫 / 大师金
  (游戏里普通是白的,浅底上看不见,换成中灰)
- 整列无数据的品质自动隐藏,并在下方说明是哪几档——不然大部分物品是一张 80% 空白的表
- URL 带 `#item/T4_CLOTH`,可以直接收藏或分享某个物品的查价页;从链接进入时
  左边列表会自动定位到该物品所在的分类
- 物品图标走**本地缓存代理**(`/api/icon/…`,PNG 存在库的 `icons` 表里)。
  让浏览器直接找 render.albiononline.com 的话,翻一页分类就是上百个并发请求,
  会被对面限流,列表里一半图标是空的。首次取 0.9s,之后 7ms

## 销量榜

`flipper history` 把成交历史抓进库,`flipper rank` 从库里聚合出榜单。
web 界面上是第三个页签。

```bash
flipper history --category crafting --subcategory refinedresources --days 30
flipper rank --window 7                          # 全服合计,按日均流水
flipper rank --city Lymhurst --sort volatility   # 单城,按价格波动
flipper rank --sort trend_pct --asc              # 跌得最狠的排前面
```

**读的是本地库,不是实时 API。** 这是有意的:AODP 的 history 只给最近一段,
自己存就能越攒越长——跑上几个月,手里就有一份上游给不了的长历史。
重复抓同一天是覆盖不是累加。

115 个物品 × 7 城 × 30 天实测**一次请求、1.6 秒、13675 条日线**,history 端点对批量很友好。

维度:统计窗口(7/14/30 天)、城市(单城或全服合计)、品质、分类/子类。
**排序点表头就行,再点一下反向**,没有单独的排序控件。每行给出:

| 列 | 说明 |
|---|---|
| 日均件数 | 窗口内成交件数 ÷ 有数据的天数 |
| **日均流水** | 日均件数 × 成交量加权均价,默认按它排 |
| 均价 / 最低 / 中位 / 最高 | 日线 `avg_price` 的统计 |
| 价格区间 | 按每行自己的最低–最高归一化的条,竖线是中位 |
| 波动 | (最高 − 最低) / 中位 |
| **趋势** | 窗口内日均价的折线图 + 涨跌幅,涨绿 / 跌红 / 震荡琥珀 / 平灰 |

**为什么默认排日均流水而不是件数**:一天成交 5 千件、单价 3 万的 T8 材料,
和一天 15 万件、单价 23 银的 T2 材料,不是一个生意。流水才是跟 1000 万本金
可比的量纲。

价格区间那根条的竖线偏左,说明大部分日子价格在低位、偶尔被拉高;偏右则相反。
波动大意味着价差机会多,同时压货风险也大。

### 趋势是怎么判的

涨跌幅来自**最小二乘拟合**,不是首尾两天相减——某天有人挂了个离谱均价,
首尾相减整条趋势就能反过来,回归用上全部点就稳得多。基准取拟合直线的**起点**
而不是窗口均值:用均值当分母时,一条从 300 跌到 10 的线会算出 -187%,
跌幅超过 100% 说不通。

光有斜率不够,还要看拟合优度 **R²**:

- `R² < 0.3` → **震荡**。斜率再陡也只是噪声,那条斜线本身不可信,方向没有意义
- `|涨跌幅| < 4%` → **平**
- 其余按方向判 **涨** / **跌**

实测下来皮革类这个月普遍在跌,木板条和布在涨,低流动性的装备则大多是震荡
(波动动辄 200%+,少量成交就能把均价带飞)。

全服口径下同一天有多城数据,**先按成交量加权成一个日均价再谈趋势**——
不然两城价格差一截时,折线会在两个水平之间来回跳,看着像震荡。

口径和扫描页一致:剔掉还没走完的当天,日均的分母是窗口内**有数据的天数**。
另一个绕不开的限制——**AODP 的 `item_count` 只统计卖单成交**,买单那边拿不到,
所以榜上的销量是偏低的一侧,真实流动性只会更高。

## 先看这个:亚服数据覆盖率

AODP 的数据靠玩家自愿上传 —— 必须有人在游戏里翻到那一页市场,价格才会进库。
亚服人少,覆盖率明显差。首次实测(66 个物品 × 6 城):

| 城市 | 有数据 | < 2h | < 6h | 中位数据龄 |
|---|---|---|---|---|
| Lymhurst | 53 | 5 | 10 | 16.6h |
| Martlock | 49 | 0 | 1 | 15.7h |
| Bridgewatch | 45 | 11 | 11 | 16.6h |
| Fort Sterling | 45 | 2 | 12 | 15.7h |
| Thetford | 29 | 0 | 0 | 15.7h |
| Caerleon | 8 | 0 | 2 | 17.4h |

**结论:6 小时阈值下,一次扫描通常只剩个位数机会。这是数据的问题,不是工具的问题。**

被过滤的最大一类是"单边数据"(只有卖价没有买价),占候选的七成以上。
想要更好的覆盖,得自己跑 `albiondata-client` 抓包补数据 —— 那是第三阶段的事。

`flipper scan` 的摘要会自动诊断这一点,并在覆盖率是瓶颈时明说。

## 几个设计决策

SPEC 之外、实现时做的判断,都会影响结果,列在这里备查。

### 排序主键是日化**绝对**收益

`daily_profit = profit_per_unit × min(可吃量, 本金买得起的量)`。

同城假设一天一轮,所以 `daily_roi` 数值上就等于单笔毛利率 —— 这个字段本身
区分不出东西。真正有信息量的是表格里的 **`本金回报`**(`daily_profit / 总本金`),
它回答的是"这条机会对我这 1000 万有多大意义":毛利率再高,只吃得下 3 件也是三瓜两枣。

### Troll 过滤比 SPEC 多一层

SPEC 的四层(新鲜度 / 偏离度 / 成交量 / 双边确认)有个缺口:
买价偏离 0.45x、卖价偏离 2.4x,**各自都在 [0.4, 2.5] 内合规**,组合起来却是 5 倍价差
—— 两边同时是 troll 单。所以加了第五层 `max_margin`(默认 100%)。

另外还拦**交叉盘**(买价 ≥ 卖价):真实市场不会持续存在这种状态,出现说明
两侧快照来自不同时间,是陈旧数据的强信号。可以用 `reject_crossed_book: false` 改成只降级。

### 偏离度阈值的实测标定

首次实测(66 物品 × 6 城,160 个有效价格点)的偏离度分布:

```
min 0.48x | p25 0.89x | p50 0.96x | p75 1.02x | p99 1.51x | max 1.56x
落在 [0.4, 2.5] 外的:0 条
```

**SPEC 给的 [0.4, 2.5] 对当前这批物品一条都拦不住** —— 高流动性精炼材料和
常见装备上的 troll 单会被真实挂单迅速淹没,真正在起作用的是新鲜度和单边过滤。

阈值先按 SPEC 保留不动,因为它是防守性的:一旦把物品范围扩到低流动性品类
或附魔装备,troll 单就会出现。想更贴合实测就收到 `[0.6, 1.8]`,代价是
可能误杀真实的价格波动。**扩物品范围时记得回头看这组分布。**

### 挂单价不等于现价

挂在现价上只能跟人并排排队,得等前面的人先成交。要真排到队首,
买单得高 `outbid_silver`,卖单得低 `undercut_silver`(默认各 1 银)。
成本很小,但不算进去会系统性高估所有机会。表格里的 **`挂买→挂卖`** 就是
要去游戏里照着填的两个数。

### 日均成交量的分母是"有数据的天数",不是窗口长度

AODP 缺失某天几乎总是"那天没人上传",不是"那天没成交"。按 7 天平均会把
覆盖率问题误算成流动性问题。代价是样本少时噪声大,用 `min_days_with_data_7d` 兜底。

同理,**当天那个点会被丢掉** —— 它是还没走完的一天,量必然偏低。

### 均价按成交量加权

算术平均会让一个零星成交日和一个万笔成交日等权,基准均价被带偏后,
偏离度过滤就会失准。

## 摩擦成本

```
市场税 4%(premium) + 挂卖单 2.5% + 挂买单 2.5% = 9%
```

**挂买单是否收 2.5% 尚未确认**,默认按收费算(保守)。游戏内确认后改
`economics.buy_order_setup_fee: false`,摩擦降到 6.5%,机会会明显变多。
这是当前最值得花五分钟去验证的一个配置项。

## 输出

终端表格 + CSV(`out/scan-<时间戳>.csv`)+ SQLite(`data/flipper.db`)。

CSV 含 SPEC 要求的全部字段,外加 `my_bid` / `my_ask` / `qty` / `capital_used` /
`capital_roi_pct` / `buy_age_hours` / `sell_age_hours` / `notes`。
`item_name` 是官方中文名。

`confidence` 三档:

- `high` — 双边数据都在 2 小时内
- `medium` — 在 6 小时内
- `low` — 任一指标贴近过滤阈值边缘(具体哪一项见 `notes` 列)

SQLite 存每次扫描快照。跑一段时间后可以回答"这条机会是一直存在还是昙花一现"
—— 只出现过一次的多半是数据抖动。

## 验收状态
